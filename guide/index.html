QUICK PAGE GUIDE

What each page contains.

A short guide for reviewing the website and finding the right code file.

Prototype only. Demo requests are saved for review. No payment is taken, and no real UWC appointment is reserved. Use test contact details.

01 / PUBLIC WEBSITE

Explore UWC & packages ↗

  • About UWC: background, services and contact information.
  • Four screening packages: price, inclusions and comparisons.
  • Build your own: search and select individual components.
  • My plan: view totals, remove items and continue to details.

Files: index.html, app.js, catalogue.js, icons.js.

02 / BOOKING STEPS

Inside the public website

  • Customer details: name, contact, email and consent.
  • Appointment: choose a weekday/morning time within three months.
  • Review: check everything before sending the demo request.
  • Confirmation: save/copy the code, download PDF or print.

Files: dialogs in index.html, app.js, appointment-rules.js, pdf.js.

03 / GUEST TRACKER

Track my booking ↗

  • Enter a booking code; no customer login is needed.
  • See the package, appointment time and request status.
  • Read messages marked customer-visible by staff.
  • Reply or suggest a new time when changes are requested.

Files: track/index.html, track.js, shared demo.css.

04 / STAFF DASHBOARD

Admin dashboard ↗

  • Sign in with an owner-approved staff account.
  • Search, filter and sort submitted requests.
  • Approve, reject, request changes or reschedule.
  • View the day schedule, notes and action history.

Files: admin/index.html, admin.js, admin-data.js, shared demo.css.

CODE QUICK REFERENCE

Where to make changes

  • Page text/structure: the relevant index.html file.
  • Packages/prices: catalogue.js, not copied price text.
  • Public design: styles.css → enhancements.css → readability.css, in that order.
  • Booking rules: appointment-rules.js; server rules must agree.
  • Database security: supabase/; keep credentials private and do not edit applied migrations.
  • This guide: guide/index.html. More detail: docs/CODE-GUIDE.md in the project folder.

Edit source files, test, run build.ps1, then push to GitHub. Updates use the same public Vercel address.
